Reproduction order:

1. Read `TEAM_SYNC_WORKFLOW.md`, inspect Git and ignored local edits, preserve unfinished binaries, and restore the entitled intake with verified hashes. Close affected editors.
2. For a **new lab only**, copy `Tools/AssetValidation/lab_template.uproject` as `AssetCompatibilityLab.uproject` and `lab_DefaultEngine.ini` into `Config/DefaultEngine.ini`. Run `prepare_lab.py`. The script uses this dated intake/lab and the local static-intake inventory; it deliberately refuses to overwrite edited lab packages. Preserve `staging.json` before adaptations.
3. Run the installed `UnrealEditor-Cmd.exe` against the lab with `-run=pythonscript -script=<absolute tool path> -unattended -NoP4 -stdout`. Inventory can use `-NullRHI`; actual captures require `-AllowCommandletRendering -RenderOffscreen` without NullRHI. Run `ue_visual_exports.py` for exchange exports/pose evaluation; prefer `ue_native_capture.py` when glTF baking is unnecessary, then `ue_pose_validation.py` sequentially, not against the same open lab concurrently.
4. Run Blender `--background --factory-startup --python <absolute blender_export_audit.py path>`. Inspect images, not only aggregate counts. FBX diagnostic files do not yet have complete relinked Blender materials.
5. After bounded adaptation, resave **only the lab** using UE 5.8.2 `-run=ResavePackages -ProjectOnly -PackageFolder=/Game -IgnoreChangelist -NullRHI -unattended -NoP4`. Do not use fixup/delete/mirror options. Run `verify_versions.py` and a fresh UE inventory. Keep pre-resave evidence to compare results.
6. For post-resave exchange files, run `ue_export_resaved.py` **with rendering enabled**, then Blender audit with `CS549_FBX_SUBDIR=UE582Resaved`. Repeat poses, preserve `ue_pose_validation_before_resave.json`, and run `summarize_results.py`. Source/header resaving and geometric FBX export have different renderer requirements.

Epic documents the resave commandlet and engine-version/changelist controls in its [commandlet API](https://dev.epicgames.com/documentation/unreal-engine/API/Editor/UnrealEd/Commandlets/UResavePackagesCommandlet?application_version=5.5); its [official issue reproduction](https://issues.unrealengine.com/issue/UE-231746) illustrates project-only `/Game` selection. Our installed engine log and header verification, not those older documentation versions, determine this lab's actual result.

## Verified structural and exchange results

All **534** staged assets loaded in UE 5.8.2. The corrected inventory has zero Python inspection errors. All **148 Texture2D** assets load; skeletal meshes have no null material slots. Early `GetSize` results can be 32-pixel compilation/streaming placeholders, not source-resolution measurements. Compare registry dimensions and completed renders before reporting resolution or texture quality. Loading does not prove correct channel interpretation or appearance.

Four complete character variants contain all **68** animation-source mannequin bones with matching parent relationships. Germans have 69 bones and US characters 73. Extra bones are not a conflict by themselves. Seven selected action families were evaluated against each variant: idle, walk, run, fire, reload, hit and death. These 28 evaluations are not a gameplay AnimBP, IK, weapon-contact or ragdoll acceptance test. A lab-only compatible-skeleton declaration is gated on this hierarchy comparison; visual/motion validation remains necessary.

All character/equipment FBX meshes have UVs, an armature modifier and no unweighted vertices in this check. All 12 exports have no zero-area triangles at the recorded numerical threshold. Five-influence vertices exist; do not force a four-influence limit without checking the actual target platform and skinning requirements. Counts are representation-specific: Unreal render vertices and Blender mesh vertices need not match because seams/material boundaries split vertices.

These are **fresh FBX exchange findings**, not proof that UE runtime exhibits the same deformation. Preserve them as reproducible diagnostics and compare with actual skinning before blaming the visible result on weights.

The M1 Garand is a one-bone UE skeletal mesh with 3,923 triangles and no physics asset. Its FBX import has no armature/weights; treat the mesh as a rigid weapon exchange candidate, not as a deformable humanoid failure. A one-bone weapon is insufficient evidence of bolt, ammunition/clip and weapon-specific reload mechanisms.

## Version standardization and handoff policy

Maintain three distinct layers:

1. **Immutable original:** delivered package bytes, source/version/provenance and SHA-256; never overwritten by engine conversion or Blender repair.
2. **UE 5.8.2 adaptation:** editor-aware imports/migrations, compatible skeleton/retarget settings, materials, physics and gameplay-facing assets. Resave the resulting `.uasset`/`.umap` dependency closure in this pinned engine. A changed engine header is a serialization result, not evidence that all defects were repaired.
3. **Exchange artifacts:** FBX for meshes/rigs/animations, textures alongside it, optionally GLB for bounded material preview, and a Blender repair source where needed. FBX/GLB do not carry the full UE materials, PhysicsAsset, AnimBP, sockets and project configuration; they do not replace the native adaptation release. Record exporter/version/options and fresh-import results.

After all required repairs and regression gates pass, create a new immutable SFTP release, verify uploaded bytes, and commit its matching per-file hashes, dependencies, ownership, pinned engine and rights records. Transfer only changed/new files. No mutable `latest` authority, no raw assets in Git and no silent overwrite of teammates' binaries. Keep one adaptation owner per skeleton/mesh/material family.
