## 结论

城市已经有，真正缺的是能在游戏里一起工作的**士兵、骨架、步枪和动作**。当前项目没有发现已通过生产验收的士兵动作组合。

最省事的寻找顺序：先找两种阵营的成品绑定角色，再找与其骨架兼容的第三人称动作，以及一套完整的第一人称手臂＋步枪＋动作包。六名角色可以复用两套基础配置，不用找六个独立模型；也不必重新逐件找头、衣服、帽子和鞋子。

## 看商品页面时检查这些

1. **有骨架不等于有动作。** 要实际文件清单和动作列表，确认不是只有一个摆姿势的人物。优先已声明版本和骨架的 Unreal 包，或带真实蒙皮骨架及贴图的 FBX；静态 OBJ 不满足士兵需求。Blender／GLB 源文件也要验证进入 Unreal 的路线。
2. **人物和动作要匹配。** 记录骨架名称、层级、参考姿势，以及动作是原地还是根运动。标注“支持 UE”不代表不同商家的动作可以无损套用。要看走跑、弯肘、握枪的实际视频。
3. **要游戏用模型，不要只看漂亮渲染。** 查 UV、PBR 贴图、材质数量、贴图规格、面数、LOD 和变形预览。没有经过测试的面数不能保证帧率；只有高模雕刻文件的先放一边。
4. **枪和装填必须一致。** 步枪的弹夹／弹匣机制、手部动作、活动部件和装填提交时刻要对得上。需要的弹药组件尽量随包一起获得，避免买完枪发现装填没法做。
5. **授权分别核对。** 三人组内共享源文件，以及最终游戏打包分发，都要确认；公开 GitHub 不等于公开模型源文件。授权、来源、版本记录在资产文档，收据、密码和账号信息不进 Git。
6. **历史配置仍需选择。** 具体日期、玩家部队、敌军编制、制服徽章和武器还未定。泛称“二战士兵”、空降兵或现代战术装备不能直接当巴黎 1944 已通过历史验收。

你找到候选后，把商品／来源链接、预览、格式与 UE 版本、骨架与动作列表、模型／贴图规格和授权说明给我。我先判断哪些能整套搭配，再安排获取和适配；本次没有采购、下载或生成新模型。

## 找到之后的入库方式

保留原始包不变，先记录来源、授权、骨架、插件和依赖再共享。本服务器的获准资产只保留一个物理存储区 `Assets/LocalShared/SFTP/`，原始基线与唯一可写工作区分开；`Assets/LocalWorking/` 仅作为过渡目录映射，不再放另一整套副本。授权未确认的入库内容保持私有。分配资产 ID 和唯一修改负责人，按[团队同步手册](TEAM_SYNC_WORKFLOW.md#6-new-assets-and-original-baselines)发布允许共享的原件和修改版本并验证字节；Git 只记录代码、配置、文档和哈希版本，不上传模型。

之后在独立兼容性地图核对：材质完整、全身变形、走跑、瞄准开火装填、受击死亡、手枪口对齐和第一人称镜头。团队集成放在 `/Game/ParisCombat`，不在磁盘上改名 `/Game/WW2City`。必须再做打包验证，对应 [ASSET-01／ANI-01](../Docs/Development/ASSIGNMENT3_ACCEPTANCE.md)。当前 UE5.8 项目关联及 UE5.8.2 基线不代表新资产已经兼容。
