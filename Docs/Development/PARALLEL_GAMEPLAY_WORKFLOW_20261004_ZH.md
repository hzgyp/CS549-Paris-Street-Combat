## 能并行什么，不能并行什么

```text
A：换弹原因定位／适配 ──┐
B：NPC树／动作请求 ────┼→ 串行城市集成 → 回归 → 人工复核
C：接口核对／测试准备 ──┘
```

代码、文档、离线资产／日志检查、确定性测试可以同时做。但本机游戏和lab均指向
同一物理SFTP Content；不同目录／地图／窗口不代表编辑器写入已经隔离。

- 首个Unreal原生制作／测试时段归A。B/C先离线工作，不同时启动UE写资产。
- A正常退出编辑器并核对保护后明确释放，B再预约原生时段，C最后预约运行回归。
- 预约只是协调规则，不是已经实现的进程锁。启动还要查UE进程；不能多窗口抢着
  启动、强关别人编辑器。归属不清先做离线工作，再找协调窗口／用户确认。
- 用户预览没关闭时，其他所有写入暂停。
- 不复制26GB底库，不另外存资产实体。原生草稿只存单一SFTP workspace Content，
  用不同的新package路径和唯一Evidence/log名字；原件和release不可写。

## 动作和交互的公共约定

NPC意图必须落到真实动作。拟新增适配器返回Started／Running／Completed／Rejected／
Cancelled、原因、TaskID／RequestID／RestoreGeneration；不能覆盖原换弹ActionID。
这还是要开发的接口，不是假装已有。已验证入口包括
PC_RequestFire(AimOrigin,AimDirection)、PC_RequestReload、PC_ApplyDamage(Amount)、
PC_ResetLifecycle，接入前核对实际签名。NPC用自己的枪／目标方向，不调用玩家相机射线。
不直接赋弹药／生命值，不用BT超时制造伤害／补弹，Running不重复启动。复位归任务／测试层。

B可基于原共享全身动作做树，不必等待第一人称精修；但射击／换弹仍需两阵营的装备、
接触和事务验证。首版不启用NPC跳跃／蹲姿／匍匐；不可用动作落待机／等待。
德军枪模已获认可，UE挂接是未选中的测试候选，不等于扳机／历史或正式地图装备验收；
不能做隐形枪伤害。
