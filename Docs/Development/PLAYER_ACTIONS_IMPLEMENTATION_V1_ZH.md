# 人物动作补齐实施方案

2026年10月3日。本轮先接入现有动作，再写双方NPC行为稿。这里只开发人物动作，不实现NPC AI，不发布资产、不提交推送。继续使用现有巴黎地图、人物和正式第一人称显示。

## 失败案例与本轮变化

已读 `Failures/README.md`、FP001 `FAILURE_ANALYSIS.md`、`WEAPON_PRESENTATION_AND_PLAYER_ACTIONS_V1.md` 和 `CONTINUOUS_ARMS_NATIVE_IMPLEMENTATION_V1.md`。FP001说明，数值对齐或原文件哈希不变不等于视觉通过。本轮不再改手指、不试更多刚性偏移、不用前臂遮罩。只改输入、移动参数及已有完整动作的选择，不改人物、骨架、手指、原动画、镜头安装位置或弹药事务。运行逻辑由UE原生蓝图控制，Python仅用于制作与测试。

## 动作与实施顺序

| 动作 | 现有资源 | 本轮接法 |
| --- | --- | --- |
| 步行与跑步 | 已有方向步幅BlendSpace与步枪跑步动作 | WASD；按住Shift提高移动速度，保留已有步幅校准 |
| 静步 | 有走路动作，未确认独立潜行动作 | 按住Alt低速走路；不声称已实现潜行或听觉系统 |
| 跳跃 | 起跳、空中、落地动作 | Space；地面起跳、引擎处理腾空；不做NPC跳跃路线 |
| 蹲下 | 蹲姿待机及前后移动 | Ctrl切换，使用引擎蹲姿与起身空间检查 |
| 匍匐 | 趴下待机及前后移动 | Z切换；低胶囊体加长身体空间检查，不能只缩胶囊就算通过 |
| 开火、换弹、死亡 | 已验证逻辑及动作 | 保留事务；不兼容的姿态或跳跃先取消换弹，拒绝不合适的请求 |

先只读检查动作时长、骨架、根运动、BlendSpace采样、人物默认值和父类接口。站姿移动继续用已有AnimBP；其他姿态可用UE原生单动作播放，回到站姿时恢复原步幅AnimBP。只在动作切换时重新播放，禁止每帧重启。若此方法无法安全处理转换和跳跃阶段，就记录失败后使用单独动画图，不修改原片段。

速度按现有采样评估后选择，不提前宣称参数正确。蹲下与匍匐只是人物能力，不自动决定NPC何时使用。没有侧向匍匐动作时，采用受限转向及前后移动，不能假装资源完整。

已核对现有制作代码：步行采样150厘米/秒、跑步采样300厘米/秒，不是600。新候选采用步行150、跑步300、静步65、蹲移120、匍匐60，避免拉伸已经校准的步幅。进一步找到已有蹲姿左右移动，纳入接入；匍匐暂不允许侧移及转向，避免横躺身体旋进墙体。蹲趴枪手接触未复核前，试验暂限制站姿开火与换弹。起跳速度先设360厘米/秒，接触与画面另验。

首轮制作因引擎隐藏的蹲姿参数失败，没有保存资产；第一个保存的候选速度未按采样匹配，保留但不选用。后续使用新名字。首轮运行观察脚本调用了不存在的Python接口，动作断言尚未开始便失败；日志保留，不能记为动作通过。

### 全身动作与第一人称持枪分开

重新加载后观察到步行、跑步、跳跃、蹲姿及换弹取消，但连续路线撞墙，匍匐空间检查拒绝首次进入，后续测试又错误地假定第一次切换成功。第三人称相机引用了编辑器世界对象，该批身体截图不能作为姿态证据。冻结的跳跃第一人称图出现袖子遮挡，不能选择这版。

下一轮新建独立的第一人称显示派生版：用已有、未修改的持枪片段驱动隐藏的原生姿态对象及现有枪械挂接类。人物全身照常跑跳蹲趴；Ready时第一人称跟随独立持枪，Reloading时跟随原全身换弹姿态。沿用已认可的显示构图、镜头及枪械事务，枪口仍绑定可见枪。原显示、玩家、人物资源不修改。这是已有动作选择，不是改骨骼、手指、IK或网格；仅运行标准蓝图，增加正确Tick依赖及EndPlay清理。早期检查持枪、换弹、枪械回归；若遮挡或弹药/挡枪退化，不能选择，最终动态画面仍需人工复核。

下一轮逐项明确复位测试起点，记录实际姿态是否进入，不假定按钮成功；使用PIE世界相机，并测头、手、脚是否落在匍匐空间包络内。真实城市里的碰撞夹具只证明局部规则，不能算整城匍匐或导航验收。地图选择等测试及内部图像检查后再做，Catalog和已发布地图保持不变。

## 目录与实施流程

最后一版安全派生增加松开跳跃键时的原生StopJumping；开火/换弹同时检查尚未落实的姿态与跳跃请求，避免同一帧先请求蹲下/跳跃、后开始站姿换弹。只建立新的V5身份，不覆盖V1至V4。功能验收不再冻结时间或切换截图相机；截图干扰属于测试工具失败，画面人工复核另行处理。

人工复核入口为 `run_player_actions_preview.ps1`：核对已发布基础与本地草稿哈希，只在未保存的真实城市编辑器世界替换玩家/显示，启动PIE后撤销一次性启动观察。运行仍是原生蓝图，不靠Python逐帧驱动动作，不生成测试夹具或保存地图。请勿保存试验编辑器地图。原`-game`入口及Catalog继续使用上一版，复核通过再单独选择/发布。

新资产使用 `/Game/ParisCombat/Blueprints/PlayerActionsV1/`，必要时增加 `/Game/ParisCombat/Animation/PlayerActionsV1/`。原生文件仍只存共享工作区的唯一Content目录；Git只记录代码、文档和哈希。不要覆盖已发布的206文件版本或Catalog。制作与测试阶段保护当前地图及43个保留文件；先在真实巴黎地图运行时替换玩家，不保存地图，视觉复核与测试通过后再选择。

顺序为：只读盘点→制作独立玩家及动作控制器→编译并仅保存新资产→关闭编辑器桥后重新加载真实地图测试→回归输入组合、枪械及生命状态→检查人物与第一人称画面→记录结果和缺口→写行为稿。失败测试使用新编号保存，不覆盖证据。

## 验收与停止条件

逐帧复查推翻runtime_v9工具返回的29项全True：匍匐报告blocked/速度零后仍向墙推进，最终位移49.12厘米，因为玩家Tick在移动组件积分之后才停止移动。“任意一帧曾停止”的断言不够严格，属于真实安全失败而非画面精修。新V6在AddMovementInput之前拦截前后输入，用请求轴方向进行预测包络检查，待进入匍匐时也拒绝侧移/转向；旧包不覆盖。墙边断言改为每帧位移上限及末段持续位置稳定。早期验收为持续按键也不推进长身体包络；若仍推进则停用匍匐，保留未选试验，使用新编号回归动作与枪械后再预览。

早期验收：新类可编译、重新加载，不依赖运行时Python或编辑器桥；原资源和已发布地图哈希不变。遇到额外脏包、原文件变化、用户正在使用引擎或必须依赖运行时Python/桥时停止写入。

测试覆盖跑步及静步的各方向、起跳腾空落地、蹲趴转换与移动、墙边和低空间的起身拒绝、长身体碰撞、换弹提交前后中断及过期事件、各姿态死亡与复位、重复请求、第一人称显示兼容性。功能通过与视觉通过分开记，必须查看多角度截图；没做的人工键鼠和接触验收明确写未做。

匍匐若不能通过长身体碰撞或地面接触，就保留未选试验并记录运行缺口，不把危险姿态上线。动作若遮挡镜头或枪手接触明显失败，就停止选择并交人工复核；行为稿仍可继续，但相关能力标记不可用。不进入无限精修或重新造人物。

回退方式是停用独立试验、保留已发布地图与版本，不把旧哈希覆盖到新的独有工作上。
