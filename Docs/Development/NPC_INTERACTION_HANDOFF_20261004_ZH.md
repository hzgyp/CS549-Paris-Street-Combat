## 实施顺序

1. **B0接口**：核对1玩家、2盟军、3德军的实际类／TeamId／共有函数。
   五NPC共用Controller／BT定义，但每个有独立控制器、BB、记忆。
   动作适配器必须有可观察的请求／反馈／generation，缺能力就拒绝，不只写状态名。
2. **B1单NPC**：敌我筛选视线、守卫／徒步巡逻、MoveTo／停止、有限等待重规划、
   生命周期取消。早期验证两NPC目击记忆独立，丢视线不再读隐藏目标当前位置。
3. **B2双盟军**：独立跟随／归队／支援点预约，抵达、待机、开火、换弹期间保留。
   只在改任务／失败／死亡／恢复时释放。短追同时约束离玩家距离和累计追敌移动；
   切目标／重新评估树不能清预算。与独立寻点做同起终点、同人数比较，只选一种避让。
4. **B3三德军**：守卫／徒步巡逻、接敌意图、最后目击处有限可达搜索；超时或没有
   检查点就回职责，重新目击才恢复实时跟踪。无枪可感知／移动，不造伤害。
5. **B4装备／事务**：复用现有M1及已认可德军模型的已测nativeV2候选，先重新验证
   双方装备／碰撞／枪口／接触；不重做枪、不买新包、不把现代枪或M1偷偷给德军。
   PC_RequestFire用NPC自身起点／目标方向，保留原开火、换弹、死亡事务。
   旧泛用全身换弹是暂定视觉限制，不在B修第一人称换弹。
6. **B5六人物交互**：停止→转向→合法开火、换弹门、命中后存活／死亡、清目标／
   释放预约／旧回调隔离。B设计统一FriendlyFireEnabled和准确共享伤害patch：
   开则实际友军命中扣正常伤害一次，关则不扣；两模式友军都挡弹，AI都避免友军枪线，
   不变阵营／不报复。共享基类由协调窗口合入，再测玩家和双方NPC作为射手。

沿用树及A00/A01/A02/A03/A04/A05/A07/A08/A10动作叶。首版不启用NPC跳跃／蹲姿／
