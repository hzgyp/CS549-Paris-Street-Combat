# 确定HUD开发基线并删除旧打包版本

2026年10月9日。[英文原文](HUD_BASELINE_RETIRE_PACKAGES_20261009.md)。
用户明确选定最新本地HUD为后续开发基础，并允许删除此前没用的打包版本。

## 已读案例、区别与早期门槛

已读HANDOFF、失败索引、MI012遗漏玩家动作、MI013旧HUD及字体失败、发布结果、
前次空间清理/恢复契约。此次将已测试hud_v3选为功能和视觉开发基线，写入
CURRENT_DEVELOPMENT_BASELINE.json及会话入口。40项已发布源码是原样起点，
已有匹配的私有Project为实际可写工作工程；旧正式源码/原生版本保留为资产
恢复锚点，后续功能/HUD开发不再从其旧代码开始。不改代码、模型、手指姿态、
枪械/资源/存档逻辑、地图和原生资产，不启动引擎。
已验收的是Game运行包，相关源码此前仅编译Game；旧Editor缓存不证明编辑器
已经显示本HUD。后续需要编辑器时，应按选定源码编译并实际核对后再使用。
先确认当前游戏49722142…d1c42b、50项试玩文件、40项公开及40项工作源码、
758项正式源与703项保护记录一致，并确认游戏/编辑器/构建进程不在运行。
最新试玩/HUD Archive/已选本地及SFTP ZIP、Content、工作源码/烹饪输入和所有
源码/日志/图像/存档保留。选择只推进UI开发基线认可，不增加整套动作、性能、
第二台电脑、自然对抗、视频或课程验收。

## 精确删除范围

冻结清单后删除11个明确生成目录：两份旧非HUD试玩、instrument_v13 Archive、
10月2日package_v3 Archive及正式Saved/StagedBuilds、六份失败instrument
v1/v2/v6/v7/v14/v15 Archive。父目录源码、构建回执、日志、截图和失败分析
不删除。本次授权只覆盖这些生成目录，替代此前保留旧试玩/Archive的快照；
其他克隆中的Archive、已发布SFTP历史不纳入。重解析点、未知文件/路径或
活动写入即停止。
旧有效/失败G1包逐文件哈希，通过已有私有V13 ZIP、最新HUD Archive、前次唯一
ZIP及新的少量唯一文件ZIP恢复，只复用大小/SHA一致的字节并实际读回用到的
ZIP成员。10月2日旧成功包的生成载荷按大小/时间和程序哈希记录退役，保留原
构建/源码证据，不承诺该旧成功包逐字节恢复；原生原件与未完成源码不算缓存。
删除instrument_v13前，把原恢复清单依赖的7项文件转接到已校验的旧V13 ZIP，
另写认证覆盖账本，原plan/result字节不改，恢复工具显式读取覆盖。
这一份旧ZIP仍是恢复依赖，因此保留，不作为第二个活动试玩版本。
不删远端release/object历史，也不调整权限。

## 执行、验收与停止

准备阶段不删除，记录SHA/大小/时间、唯一ZIP及恢复转接。执行仅用PowerShell7
LiteralPath和硬编码工作区白名单，先查绝对路径/重解析点、活动进程、清单
身份、实际文件集合和备份字节；每个递归删除前再次确认无运行进程。
任何不一致/失败即停止，不自动关闭用户游戏。最后确认11项不存在，当前
试玩/源码/资产及恢复引用仍一致，记录真实可用空间增加及前后回执。
此次不提交推送Git、不启动引擎，也不增加资产发布或运行验收。
