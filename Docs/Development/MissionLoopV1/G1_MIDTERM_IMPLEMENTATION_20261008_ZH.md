## 任务和存档规则

状态为 Preparing、Ready、Crossing、Clearing、Occupying、Won、Lost、Error。用运行时 Actor 标签封闭登记六个稳定身份，不依赖编辑器名称。每次新世界使用新代际。Ready 禁止玩家移动／开火／装填及 NPC 行为。Enter 开始，F5 存档，F9 读档，Ctrl+R 从初始配置重开；单独 R 保留原装填。HUD 显示当前目标、剩余守卫、真实资源、存读反馈及操作提示。

Crossing 要求活着到达 T1；从开始就记录合法 G1 死亡，Clearing 要求三人全部真实死亡；随后活着进入 G1 占领范围。统一在原伤害／死亡更新后推进，先判玩家死亡。结算锁住新的行动。盟军死亡不补人。

F5 只在安全稳定边界保存：身份完整、活人落地、无进行中的开火／装填、无当前敌对视线或已准入敌对行动。不安全时说明原因且不改状态。Won 可保存；Lost／Error 不覆盖好档。记录版本、任务／配置指纹、序号、阶段／死亡记录、六人身份／类／变换／生命／弹匣／备弹／开火序号，以及玩家控制朝向。存档不改变资源。

双槽轮流保存，载荷带校验和及递增序号；写入非当前槽后重新读取验证才报告成功，不在一次操作中覆盖两个槽。应用前校验版本、配置、完整性、六个唯一身份／类、数值范围及阶段／死亡一致性。选择最新有效兼容档；明确报告损坏／不兼容。两个都无效则停留当前局，不做部分恢复。此机制保留上一有效档，不声称文件系统原子写或云同步。

读档先验证，再带明确加载请求重开新任务地图。在新世界的受控装备准备后，通过原生命周期接口失效旧动作代际，恢复准确位置／资源／朝向，并通过原死亡逻辑恢复已死角色。全部核验后才启动原行为树；不恢复半次装填、旧目标、感知、占位或定时器。已死者继续死亡。必须关闭进程后在新进程复现，不能仅验证内存读档。

完整重开忽略存档，回到初始六人配置并更新代际；检查无重复枪、适配器、控制器或策略。正常推进不调用此重置。

## 开发与验收顺序

1. 创建独立运行时／控制器／地图及恢复、增量清单；编译并核验保护依赖。
2. 通过十秒 Ready／Start 早期门槛，检查玩家原控制、绑定、资源和独立 Blackboard。
3. 保存并重开导航，实测玩家与双盟军同时过桥、德军站立和双方遭遇；区分路径查询失败与实际身体失败。
4. 检查顺序、提前击杀、盟军伤亡、玩家死亡、重试／重开及角色丢失错误。为测试调用原伤害接口须单独标记，不能冒充自然战斗。
5. 保存非初始有限状态并关闭进程，新进程准确恢复位置、生命、弹药、伤亡、目标；检查无档、不安全拒绝、校验／版本拒绝和双槽保留。
6. 以 `-game -DisablePython` 且关闭编辑桥运行新保存地图，检查真实画面和日志；同步记录中英结果及未过门槛。

G1／存档功能通过仍不代表课程交付完成：1080p／60 FPS、压力演示、2–3 分钟视频、进度 PDF、可玩打包／第二机器访问以及课程前置批准继续独立验收。
