## 1 目的与交付边界

资产工作台帮助团队查找购买和自建资产，查看实际外观与迭代历史，确认游戏使用的精确版本，并在购买或制作下一件资产之前写清要求。首版是本机运行的只读目录和需求模板，后续再加入受控的任务登记与评审。

用户本轮授权编写功能和技术文档。本修订规定未来软件行为，不表示已经实现服务、选择新游戏基线、购买或发布资产，也不重新开启已经停止的详细人物制作实验。

V1的目标是：组员打开五类代表性资产中的任意一类，就能找到来源、相关版本、实际游戏证据、使用位置、待解决问题和新增资产规范，无须手动查找多个目录。

## 2 现有基础与缺口

项目已经通过[CATALOG.json](../../../Assets/Sync/CATALOG.json)及其选定manifest记录不可变资产文件与哈希。[团队同步规则](../../../Assets/TEAM_SYNC_WORKFLOW.md)区分公开源码元数据、私有资产字节和本机待验证交付。工作台必须沿用这些权威来源。

早期[资产登记表](../../../Assets/ASSET_REGISTER.csv)仍有士兵和第一人称资产未选定的条目，后续整合记录已经说明正式采用情况。[下载资产清单](../../../Assets/XIAN_YU_ASSET_CATALOG_20261003_ZH.md)还记录过通过实际字节确认的重复动作交付。因此应关联带日期的记录和精确身份，不能用目录名字或最新一段文字直接推断当前状态。

本设计时点：本地正式玩法基线是enemy-clear v3，最新UI选择器记录未正式选定的candidate_ui_v5，Catalog中的已发布试玩包仍是audio V2。这是三种不同用途的选择。首页必须分别显示来源与观察时间，不能合并成一个全局“最新版”。后续刷新应重新读取选择器。

## 3 使用者与职责

| 使用者 | 主要任务 | V1能力 |
| --- | --- | --- |
| 团队成员 | 找资产、了解兼容性和实际使用情况 | 浏览、筛选、比较、查看证据、复制需求模板 |
| 资产负责人 | 准备有边界的采购或适配任务 | 查阅需求、保护约束和已有替代方案 |
| 整合负责人 | 审查精确版本与发布依赖 | 查看选择器、依赖缺口、冲突和证据范围 |

这里描述工作职责，不创建新账号或指派人员。V1由当前Windows用户在localhost使用。实名评审和多人认证属于后续阶段，共享SFTP账号不能代替评审人的身份。

## 4 资产和版本概念

| 概念 | 含义与例子 |
| --- | --- |
| 原始交付包 | 购买包或原始批次，例如同时包含网格、材质和动作的士兵包 |
| 逻辑资产 | 团队长期识别的对象，例如德军步枪外观或地雷道具 |
| 资产修订 | 该对象某次修订的不可变源文件和导出文件身份 |
| 整合修订 | 将资产连接到特定游戏源码的绑定、材质、插槽、适配器和配置 |
| 构建选择 | 用于本地正式开发、候选评审或发布下载的源码、程序和依赖组合 |
| 验收证据 | 与精确对象和明确测试范围绑定的带日期结果、图片或评审 |

一个交付包可以提供多个资产，一个资产也可以依赖多个交付包。握姿或运行时适配器变化可以产生新的整合修订，而模型字节保持不变。版本历史允许分支，编号更大不代表已经通过或采用。

使用关系必须标明依据：文档绑定、扫描到的包引用，或实际运行观察。依赖引用不能证明某个角色已经出现在游戏中。关系尚未解析时直接显示缺口。

| FR03 | 资产详情 | 展示来源、版本、尺寸与技术事实及其出处、依赖、实际用途、证据和遗留问题 |
| FR04 | 版本比较 | 比较两个精确修订，展示父版本与分支、文件和参数变化、图片与取舍原因；保留否决及退休记录 |

| FR06 | 证据与验收 | 技术、外观、人工、选定、发布结果分开；显示精确对象、范围、时间及证据是否可访问 |

| FR08 | 目录健康 | 展示过时来源、选择器冲突、缺预览、字节未核验、许可未知及疑似重复交付 |
| FR09 | 本机安全浏览 | 只提供已登记且对当前使用者允许的预览；仅克隆源码也能浏览；V1不包含模型覆盖、恢复、删除或发布操作 |
| FR10 | 刷新与来源 | 将登记的元数据刷新为一致快照；关键导入失败时保留上一次有效快照并解释错误 |

### 5.1 资产库与详情

卡片优先显示代表图、名称类别、来源路线、生命周期和使用标签。购买、自建、基于现有资产改造分开标识；改造资产保留原始来源关系。音频在本机存在且许可允许时提供播放和时长，不自动播放任何媒体。

详情按概览、版本、使用、证据、需求分栏。重要事实附来源入口，未知值显示“未知”，不能显示为零或通过。技术预算和实际测量值分列。

统计区分逻辑资产数、交付包数、文件条目数和唯一字节对象数。重复manifest及junction别名不能增加模型数量或物理存储估算。只有manifest大小时，V1可以明确将实际磁盘占用列为未知。

### 5.2 预览与比较

V1使用已有且允许当前受众查看的图片及本机音频。图片区分供应商参考、Blender预览、重新导入检查和真实UE截图。图片必须绑定修订及证据，不能仅按文件名推断。

左右比较说明相机及环境差异。只有记录能证明条件一致时，才提供“同视角比较”标识。图片缺失时仍保留证据条目并说明可用性，历史和被否决候选继续可查。

浏览器三维预览作为后续增强，仅接入经过审查的GLB预览副本。它用于浏览；UE截图和运行证据单列，因为材质、照明与行为可能不同。

### 5.3 构建与使用

页面先提供FR01的三种选择用途，以及不同候选流的选择入口。完整源码和Game身份可展开查看。必须区分模型最初采用的时间与当前原生资产包的选定版本。

路径冲突、依赖缺失、别名未解析或启动入口过时都应形成可见问题。找到一个未引用文件不等于可以删除。已退休可执行文件可能有恢复映射，应展示映射，不能声称旧路径仍存在。

## 6 独立的状态维度

| 维度 | 状态或信息 |
| --- | --- |
| 生命周期 | 待入库、候选、保留、否决、退休；退休必须说明针对哪个修订或产物 |
| 许可 | 未知、受限、允许指定受众和用途；记录依据及声明类型 |
| 可用性 | 本机存在、记录为远端存在、某日期远端已核验、缺失、可恢复、无权访问 |
| 验证 | 未运行、通过、失败、不完整、继承、未评估；每项附范围 |
| 人工评审 | 待评审、接受、否决、带限制接受；附精确对象和决策依据 |
| 选定 | 被某个用途或构建选定，或未选定；从权威选择器推导 |
| 发布 | 仅本机、记录为已发布、无法取得验证依据、发布版本已退休 |

不设置一个笼统的绿色“全部验收”标签。正式采用的模型仍可有已知接触问题，传输成功不能算外观通过，私有三人共享声明也不能解释成允许公开下载或覆盖所有派生作品。

原始记录保持不变。修正或后续决定链接并替代某一条具体旧结论，保留双方日期。继承结果必须解释哪些未变化的文件或行为支撑继承，以及哪些新检查尚未完成。

## 7 新资产需求模板

V1提供下表的可复制文本，V1.1再保存和评审结构化任务。购买交付与自建工作都使用这些字段。

| 字段组 | 必填内容 |
| --- | --- |
| 用途 | 名称、负责人、任务用途、观察视角、观看距离、预计同时出现数量、目标构建 |
| 已有替代 | 搜索现有购买包和资产的结果，复用／改造／购买／新建路线及理由 |
| 历史身份 | 涉及时填写年代、阵营单位、型号；虚构道具和不确定身份明确标识 |
| 外观 | 轮廓、厘米尺寸、比例参照、可读细节、材质意图、参考来源 |
| 技术预算 | 按类别和用途填写三角形／LOD、材质槽、贴图、可测内存的目标和硬上限 |
| 整合 | 引擎和工具目标、原点与坐标轴、碰撞规则、骨架插槽、挂接、必需动作和依赖 |
| 保护对象 | 必须保持的精确资产、手指姿势、骨架、动作、接口和玩法事务 |
| 交付 | 可编辑源、导出、纹理、依赖清单、来源许可记录、普通视距与细节图、重新导入结果 |
| 验收 | 具名自动检查、UE外观／运行用例、人工评审、测量环境和每项所需证据 |
| 停止与恢复 | 已读失败案例、本次改变、早期验收、停止条件和原件保留方式 |
| 共享 | 接收者、允许用途、证据引用及待确认事项；私有凭证继续私有保存 |

预算字段不能空置，需填写数字和单位，或明确说明不适用理由。不对所有资产强行规定同一面数。已有资产测量值只能作为例子，不能自动成为新任务已批准的预算。

人物任务要求先找现有有许可的网格、骨架和动作，再做有边界的适配；已经停止的AI详细士兵制作路线保持关闭。动作任务先搜索购买包内成熟动作，填写源动作及目标骨架；登记任务不自动授权新动作制作、采购或整合。

### 7.1 地雷资产族示例

现有结果记录的是自建虚构外观道具：盘体28厘米、10809三角形、1024贴图。这些是该资产的历史测量或描述，不是新预算，也不证明真实历史型号。关联[地雷结果](../MissionLoopV1/PRESSURE_MINE_RESULT_20261011_ZH.md)、模型审查和精确Game证据。

Blender／GLB审查、UE黑色失败候选和纠正后的UE整合分别展示。两次UE整合之间原模型可以完全相同。人工采用状态仍由评审和选择记录决定。

## 8 工作流与分期

| 阶段 | 交付能力 | 退出条件 |
| --- | --- | --- |
| V1早期门槛 | 登记来源导入和五类代表资产 | 扩展界面前先正确处理稳定身份、独立选择用途、失败及缺失证据 |
| V1完整交付 | FR01–FR10只读页面与可复制模板 | V1用例通过，用户能找到精确使用情况及证据 |
| V1.1 | 本机结构化任务草稿、评审决定和元数据变更提案 | 具名决策、冲突检测、草稿写入可恢复；不自动选择基线 |
| V1.2 | 可选GLB浏览和有界UE元数据导出 | 每条支持路线通过预览来源及匹配引擎兼容检查 |
| 后续团队部署 | 认证后的团队访问及单独限定的发布流程 | 受众许可、认证、审计和发布门槛完成设计并验证 |

未来入库流程为：搜索已有内容→记录需求与路线→本机保留原始交付→形成有界候选→技术和UE检查→人工评审→明确整合选定→另行授权并核验发布。失败候选保留身份和原因。

V1不提供自动生成模型、购买、原生资产编辑、批量迁移目录、孤立文件删除、SFTP上传、Git推送、启动游戏或通用命令执行。这些操作需要独立的实施与授权范围。

## 9 验收计划

以下是未来检查，不是已完成结果。试点覆盖德军人物／骨架、盟军人物／骨架、第一人称手臂与枪械组合、地雷、录制音频。所有当前Catalog组进入组与文件索引，初期只要求这五类有经过整理的语义关系。

| 编号 | 检查 | 预期结果 |
| --- | --- | --- |
| AC01 | 用当前选择器打开首页 | 本地enemy-clear、UI候选、已发布audio V2清楚分开且均有来源 |
| AC02 | 用中英文名称查找五类试点 | 到达正确卡片、修订与出处；人工走查目标为30秒以内 |
| AC03 | 比较地雷失败和纠正后的UE整合 | 失败图片／结果仍为失败，相同模型不标作重建，不虚构当前人工采用 |
| AC04 | 仅有源码或缺少私有预览 | 元数据仍可用，说明缺失／无权访问，不伪造图片或通过结果 |
| AC05 | 查看德军外观选定和限制 | 正式取舍与仍存在的接触限制按各自范围同时显示 |
| AC06 | 查看重复动作交付依据 | 展示重复字节关系，不自动删除，也不计为新增可用动作 |
| AC07 | 从构建追踪资产再反向查询 | 精确已解析关系或明确缺口；依赖引用与运行观察区分 |
| AC08 | 复制新道具或人物需求 | 字段、适用约束、早期门槛和停止条件完整，保留现有资产优先政策 |
| AC09 | 刷新损坏、变化中或冲突的元数据 | 关键错误保留上次有效快照，非关键证据缺失显示可用性下降 |
| AC10 | 浏览媒体并操作V1所有控件 | 只显示登记且允许的媒体，不写源文件或资产，不显示未支持的变更按钮 |
| AC11 | 查看exit0但没有完整结果的运行 | 显示不完整或夹具错误，不能根据退出码判定通过 |
| AC12 | 检查1920×1080和1366×768 | 搜索、筛选、证据标签和比较可读，键盘可操作 |

性能目标：在已记录配置、至少20000条文件索引的夹具上，本机预热查询p95低于500毫秒；服务及索引就绪后首屏2秒内可交互。元数据、媒体加载和完整文件核验分开测量。这些是设计目标，并非已有性能成绩。

## 10 失败经验与停止条件

本设计已读案例包括[MI030](../../../Failures/MI030-20261011-mine-render-winding/ANALYSIS.md)、[MI033](../../../Failures/MI033-20261011-ui-screenshot-timing/ANALYSIS.md)、[MI035](../../../Failures/MI035-20261011-ui-restore-fixture-alias/ANALYSIS.md)、[MI036](../../../Failures/MI036-20261011-ui-ready-selection-fixture/ANALYSIS.md)、[GP010](../../../Failures/GP010-20261004-german-rifle-native/FAILURE_ANALYSIS.md)。

本次改变是将每条结论绑定到精确对象和证据范围，展示失败与未知，将索引和源文件修改分开。真实像素、运行实例行为、完整测试结果分别需要对应证据。

界面扩展前必须通过早期门槛：正确区分三种选择用途，并展示地雷失败、私有文件缺失和测试不完整。如果发生保护文件被写入、用途混淆、不完整证据被标为通过、泄露未获准预览、跟随未登记存储别名，或必须放宽既有许可／验证规则才能继续，应停止相关实施步骤。保留诊断和上一次有效索引，修正适配器或设计后继续。
