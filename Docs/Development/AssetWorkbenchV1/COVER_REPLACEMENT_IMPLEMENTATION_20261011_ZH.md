# 封面替换实施 — 2026-10-11

用户要求移除采购/供应图片及水印封面，使用实际打开资产取得的截图替换。当前登记有126张供应商宣传图，覆盖125个动画包和合集。处理范围为本机平台显示与私有预览，不删除采购原始凭证，不改写模型、骨架、动作、原生项目、Catalog和其他窗口的UE会话。

已读MI030（实际渲染不可由数值替代）、MI033（完成截图后才切换对象）及本平台3D结果。采用已有UE原生加载、瞬态世界和SceneCapture流程，在独立预览工程解包/打开原生资产；每个包选择自身真实骨架与动作截取代表帧，保留资产路径、动作时间、输入哈希、引擎版本及输出哈希。不同动画包隔离加载，避免同名包污染。不使用宣传图裁切、去水印或生成图替代真实资产。

先移除所有供应图片引用并阻止库存重建恢复，缺图阶段明确显示待预览。早期门槛：首个包实际加载、骨架匹配、完整取景、图片有可辨模型且无宣传水印。通过后批量展开；停止条件为包加载失败、骨架缺失/不匹配、输出空白、取景裁切或资源预算不足。失败项保留诊断，修复导入条件后重试新身份，不拿别的包图片冒充。全部成功截图验证后登记为新封面，再检查分页、详情、原有3D及中英显示。原件和历史证据不覆盖，截图留在私有目录。

## 实施修正（同日）

首次UE实际截图加载成功，但旧交付的材质引用不完整，出现错误棋盘材质，因此仅留作诊断。改为UE实际加载原始网格和动作，将带预览模型的动作一起导出FBX，再由Blender打开并用中性材质捕获。所有最终封面标明中性材质，不能当作原材质验收。

NullRHI两次导出触发SkinnedMesh断言，停止此路径；使用实际D3D12 RHI加载。早期模型/动作分别导出时，仅验证骨骼位置不足以保证绑定，发现姿态偏差后停止登记，最终全部采用UE联合导出，禁止Blender重绑/重定向。FBX导入帧率取实际导入值；封面标注动作名和导出时间轴位置百分比，不把导出帧率差异说成原生精确时间对齐。取景依据实际变形顶点投影，四边均保留至少5%空间。

Movement Animset Pro交付仅含动作，引用缺失的标准UE4人偶骨架。在独立预览工程补充已持有Hammer包的标准人偶依赖，通过包路径重定向解析该依赖；原动作字节不变，不保存原生包。此一项明确标注“外部预览人偶”，记录依赖包与文件哈希，不能声称该模型随Movement包交付。其余包只使用自身交付的网格、骨架和动作。

最终执行入口：`prepare_native_covers.py` / `group_native_covers.py`（私有副本）、`ue_export_combined_cover.py` / `run_combined_cover_exports.py`（export-v4）、`blender_capture_combined_covers.py`（capture-v8）、`review_native_covers.py` / `register_native_covers.py`。Movement依赖修复另由 `ue_export_movement_cover.py` 执行。早期脚本、失败结果与图片保留作为诊断，不登记到平台。

平台限制分别放在库存导入、快照建索引和媒体读取三处；旧快照的供应图返回410。原购买凭证不删除。新增截图、FBX、中间副本和审查拼图均留在忽略的LocalWorking中，不进入公共Git。页面继续保留现有3D功能；本次封面生成不等于新增125个在线3D动画预览。
