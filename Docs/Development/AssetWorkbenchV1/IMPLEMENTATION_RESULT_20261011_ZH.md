## 实际技术选择

- React／TypeScript＋Vite由FastAPI同源提供，监听loopback。SQLite使用DELETE日志和事务激活不可变快照；实体族保存为JSON行，快照／文件／任务使用关系表和索引。初始缓存schema为1，不宣称已实现未来完整升级框架。
- Python依赖固定在`requirements.lock`，前端使用`pnpm-lock.yaml`，替代设计中示意的npm命令；安装脚本执行冻结安装与生产构建。
- 默认8765被不相关PID 22664占用，已保留；忽略目录配置选用8766。启动器按venv精确命令行和父子关系确认服务，不假定启动器PID等于监听PID。
- 会话cookie、CSRF、Host／Origin检查、媒体ID、精确哈希、签名、有界读取和Windows实际句柄路径限制本机访问。没有执行项目命令或编辑上游资产记录的接口。
- 9份明确登记的预览直接引用已有字节，未复制进公开源码。缺失私有媒体／证据显示占位或目录问题；导入不遍历Content、不跟随junction。首版没有隐式可信junction例外。
- 构建关联是人工整理的资产族文档绑定，界面明确区别于新运行观察或全量依赖扫描。未打开或保存原生包。

## 保留的失败与修正

1. pnpm初次阻止esbuild安装步骤；在`pnpm-workspace.yaml`明确允许该已知构建依赖，重建后冻结安装通过。
2. 初次绑定8765失败；保留既有服务，改用8766，保留原启动日志。
3. 启动器将venv父PID当成实际服务PID而超时；修正归属检测后，启动与复用均通过。
4. 直接刷新`/assets/recorded-audio`被误判成静态文件404；现在只有带文件扩展名的静态资源走该路径，其余资产详情返回SPA。后端回归和浏览器音频详情加载通过。原图／错误／报告保留在`runs/failures/deep-link-v1`。
5. 未授权媒体负向测试预期403，而导入器实际将其排除并记录`RIGHTS_NOT_ESTABLISHED`，接口因此为404。夹具改为核对排除和问题记录，未放宽访问规则。失败XML保留在`runs/failures/media-denial-expectation.xml`。
6. 筛选控件的嵌套标签包含选项文字，精确可访问名称定位超时；已为许可和负责人加入明确aria-label，完整流程复测通过。原记录保留在`runs/failures/filter-accessible-name`。
7. 一次性编辑辅助脚本因Windows默认GBK解码在写入前失败，后用Unicode安全补丁完成；另一次辅助脚本使用了错误工作目录，也在写入前失败，已用精确路径补丁完成。随后安装命令成功不被当成该编辑成功。

`ui-results-before-service-ready.json`是名称不准确的较早复制件，内容实际记录详情深链接失败，不是初次缺少会话的启动失败。保留历史名称，以明确命名的失败目录解释内容。没有将失败结果当成资产通过证据。

## 验收限制与后续

V1不含任务编辑、线上审批回写、三维查看器、公开托管或自动资产生成，维持V1.1／V1.2边界。后续可继续将资产整理进版本化映射；增加来源或媒体适配器须保留同样的权威和受众约束。本任务没有Git提交／推送或SFTP发布。
