# MI014：读档重播死亡动画、游戏／视频无声

2026年10月9日。[英文原文](FAILURE_ANALYSIS.md)。用户发现初稿01的 F9 后德军
重播死亡动画，并反馈走路／跑步／开枪／死亡没有声音；要求修复后改为纯英文
字幕重录。这不否定现有模型／握姿／HUD和有效的资源／确认／存档检查。

ApplySnapshot 的死亡／资源恢复数值正确，却调用普通 PC_Die。该入口执行
生命周期保护并从0播放 Rifle_Death_3。dead=true不等于直接呈现终态尸体。
应保留保护副作用，但仅在恢复时跳到原片末帧、不触发通知、停播并求值；
恢复前暂不展示未还原的世界。新战斗死亡仍走原来的动画过渡。

初稿01启动有 -NoSound，OBS音轨也关闭；这是录制选择，不能作为有声演示。
用户普通游戏日志已有 WASAPI播放设备初始化；麦克风输入警告不是输出无声
的诊断。源码／蓝图作者路径未接脚步／枪声／死亡声音。必须确认现有声音资源
和打包游戏真实输出，计数器、剪辑后加声或仅启用设备都不够。

保留原基线／试玩包／用户存档／初稿和原片／出处。新私有修订从 hud_v3开始，
真实游戏事件发声，读档后初始化跟踪，切世界释放音源，验证旧存档兼容。
不重跑已停止的 RHI／GDI录制，不改模型／手指／枪械规则。
遵循[修复与重录实施文档](../../Docs/Development/G1_DEATH_AUDIO_VIDEO_REVISION_20261009.md)。

本轮另外保留的失败与诊断：

- V1 辅助代码在 TSharedRef 上再次调用 ToSharedRef，编译失败；先冻结42份源码
  和日志，V2只修正两处实参。
- V2后台检查点测试虽然音效计数增加，实际混音全为0。UE默认失焦音量为0，
  前台也被挡住；计数不能作为音频验收。前台V2动作末段取得真实非零输出。
- V3首轮检查点又被新程序路径的防火墙提示挡住，数值有效而音频为静音。
  两轮均保留，不自动处理安全提示，也不把静音混音改写为录制成功。
- UE按设计会给超出衰减范围的短声音返回空组件；最初倒地音效只有23.4米范围，
  三次远距离击杀全部被裁掉。单独为倒地装备撞击设置61.2米衰减范围，脚步范围
  保持，范围外显式跳过播放。

V3在明确记录的录制进程后台音量覆盖下，实际48kHz立体声混音包含9次有效开枪
和3次真实死亡，未削波；新死亡原动画从头正常播放。读档尸体停在3.933333秒，
首次／三秒后跟踪均为0事件／0音源；原HUDv3的V5存档也通过同样终态与生命周期
检查。正常试玩保留引擎默认失焦静音。这些不代表OBS音画对应、压力／性能或
课程验收，新视频仍需独立真实捕获和媒体检查。
