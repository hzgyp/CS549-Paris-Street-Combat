# Formal-map verification sources

Read the bilingual MissionLoopV1/FORMAL_ROLE_SQUAD_TEST_PLAN and RESULT first,
plus Failures/ML008–ML011 and NI002/NI003. The completed bankV3 launcher is
locked against automatic physical reruns. A subsequent changed implementation
needs a new bounded plan/bank and explicit reconciliation of prior negatives;
never erase originals or move targets to turn a failure into a pass.

- `prepare_cases.py`: one-time offline frozen selection from audited pure-map
  walking/floor evidence; original banks/rejected candidates remain private.
- `build_helper.ps1`: build the separate disabled Editor-only native observer;
  preserve the older pure-map plugin and actual engine ownership.
- `ue_verify.py`, `run_verification.ps1`: unique unsaved native entries; original
  bodies, PC possession, controllers and accepted presentation. The height-only
  once-per-controller bootstrap latch is separately documented, not gameplay.
- `audit.py`: original native request/arrival/resources/exit/log/guard audit.
- `audit_interactions.py`: independently rederive visibility/new-shot/casualty
  gates for passed and negative encounters; distinguish unadmitted staging.
- `summarize.py`, `plot_results.py`: unique private aggregate and measured
  diagram; no mission layout or whole-map connectivity assertion.

Receipts, binaries, native map/model-derived images and plots stay in ignored
local SFTP workspace Evidence/FormalMapVerificationV1 and tmp/formal-map-v1.
No asset/map/config save, Catalog change or publication is part of these tools.
Evidence reports actual300cm/s/normal-time tests, not FPS or Shipping acceptance.
