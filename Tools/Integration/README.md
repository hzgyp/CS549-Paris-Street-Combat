## P2 Character movement draft

With editors closed, copy only the resulting compiled Binaries to this task-owned plugin's ignored Binaries directory. Preserve source and build logs; never make it a runtime gameplay module.

`ue_character_movement_author.py` enables the bridge along with PythonScriptPlugin/EditorScriptingUtilities in the authoring commandlet. Existing packages cause refusal. Its explicit `-ParisResumeMovementDraft` path is a **one-time hash-guarded recovery of the initial instance-editability failure**, not a general overwrite/rebuild command; it cannot be used after any of those draft hashes change. The failed attempt is embedded in the recovery report. Do not rerun generation over the current scene.

`ue_character_movement_reopen.py` uses a fresh NullRHI process with `-DisablePlugins=ParisEditorBridge` and no bridge in EnablePlugins. `ue_character_movement_probe.py` uses rendering-enabled commandlet flags and the bridge. It advances the normal engine frame counter inside the commandlet loop so engine tick tasks and skeletal poses are not suppressed as duplicate work in one outer frame. This is not PIE, keyboard/mouse, AI/NavMesh, city contact, simultaneous six-character performance or a packaged test. It reports numeric movement/capsule/contact and CPU-skinned geometry, and front/side captures at selected 60-step/s checkpoints. A single phase-end image is not a full gait/deformation or foot-slip test.

Evidence is in runtime `Evidence/P2/Movement/`. The first two movement attempts and captures are preserved; v1 capture filenames have PNG suffixes but contain EXR data due to an initially unset render-target format, and are not accepted PNG evidence. Current v3 probing refuses existing report/capture identities; choose a new explicit identity for another run. Inspect JSON assertions and image bytes, not just commandlet exit code.
