# Paris integration tools

Follow [the implementation plan](../../Docs/Development/CHARACTER_AND_WEAPON_IMPLEMENTATION_V1.md) before using these scripts. These tools target the active Paris project, unlike the isolated character-lab capture tools. Use UE 5.8.2. Asset and evidence bytes stay in ignored SFTP working storage; scripts are source code.

## P0 one-time storage relocation

`relocate_runtime_storage.ps1` is an administrator-only, fixed-target migration, not a daily synchronization command. It refuses an occupied destination, affected editor processes, reparse-point source trees, unexpected files and changed catalog hashes. It verifies the city and the complete native character closure before moving anything, moves on the same volume, verifies retained bytes and creates checked aliases at the old paths. The shared account inherits Modify below the protected SFTP root; originals and immutable release objects are not edited.

Read `tmp/paris-integration-20261001/storage.json` for actual completion or a partial failure. Never rerun after a partial move: inspect its exact moved paths and repair only the missing alias/placement with editors closed. Do not recursively remove junctions or their targets.

## P1 read-only active-project probe

Run `ue_active_project_probe.py` through the active descriptor using `UnrealEditor-Cmd.exe`, `-EnablePlugins=PythonScriptPlugin,EditorScriptingUtilities`, `-run=pythonscript`, an absolute `-script` path, `-NullRHI`, `-unattended`, `-NoP4` and a task-specific `-abslog` path. Enabling these plugins for this process does not rewrite the project descriptor.

The wrapper selects the four character mount roots in `Tools/AssetValidation/ue_inventory.py`; it does not load every city asset. It loads the city World package object and records the four persisted eye bindings, native dependency metadata and exposed editor APIs. It saves JSON evidence, not UE packages.

Evidence destination: `Assets/LocalShared/SFTP/workspaces/yg745/paris-gameplay-v1/Evidence/P1/`. Check `active_project_probe.json` and the inventory's errors/completion fields, not the process exit code alone. NullRHI is a structural check only: city streaming, lighting/material appearance, deformation, collision, NavMesh, gameplay, packaging and performance require separate tests.

## P2 bounded presentation and fresh reopen

`ue_character_presentation.py` requires a successful P1 report. Use the same active-project Python commandlet entry point but replace `-NullRHI` with `-AllowCommandletRendering -RenderOffscreen`. It refuses an existing dated preview map; do not bypass that guard to overwrite another editor's scene. It generates six SkeletalMeshActor previews, samples seven in-place action families on four adapted meshes and captures two group views under controlled lighting using the project's renderer. It saves only its new team-owned diagnostic map; no native character/action/skeleton resave is requested.

After the rendering commandlet has exited, run `ue_character_preview_reopen.py` in a fresh NullRHI process. It checks the saved six actor mesh/action defaults without saving packages. Neither test implements playable Character Blueprints, navigation, weapon attachment or action transactions. Inspect actual `Evidence/P2/` JSON and PNGs before recording a visual result; a generated PNG is not automatically accepted appearance.

`ue_character_face_review.py` reopens the saved map with rendering enabled and captures four reference-pose heads from front/three-quarter views using unsaved shadowless fill. It was added because the initial posed head views were shadow-obscured. It does not change/save character assets or the level. Preserve both sets of evidence; controlled fill does not pass actual city lighting or facial animation.

`verify_runtime_storage.py` is the one-time post-relocation alias/count check and authenticated local SFTP CRUD probe. It requires the selected workstation's private key/known-host files; their contents are never printed. It uses a unique task-owned probe directory and removes only its exact verified probe file/directory. Run before P2 adds a map, since its initial file count is intentionally fixed at 16,390. It is not an asset uploader or daily overwrite/mirroring tool.

## P2 Character movement draft

The project plugin `Plugins/ParisEditorBridge` is **Editor-only and disabled by default**. Its demonstrated purpose is creating standard K2/AnimGraph nodes not exposed by the installed Python reflection. Generated graphs do not call it or inherit its classes. Build its `.uplugin` using UE 5.8.2 `RunUAT.bat BuildPlugin`, with a new, checked, ignored `tmp/.../EditorBridgeBuild_*` output, `-HostPlatforms=Win64 -TargetPlatforms=Win64 -StrictIncludes`. Do not reuse an occupied `-Package` output: AutomationTool may delete it. BuildPlugin creates an empty host containing the plugin, not a copy of city/model Content. With editors closed, copy only the resulting compiled Binaries to this task-owned plugin's ignored Binaries directory. Preserve source and build logs; never make it a runtime gameplay module.

`ue_character_movement_author.py` enables the bridge along with PythonScriptPlugin/EditorScriptingUtilities in the authoring commandlet. It creates shared Character, player/NPC child Blueprints, two velocity-driven locomotion AnimBPs/BlendSpaces and a separate six-Character movement map. It saves only new team-authored draft packages. Existing packages cause refusal. Its explicit `-ParisResumeMovementDraft` path is a **one-time hash-guarded recovery of the initial instance-editability failure**, not a general overwrite/rebuild command; it cannot be used after any of those draft hashes change. The failed attempt is embedded in the recovery report. Do not rerun generation over the current scene.

`ue_character_movement_reopen.py` uses a fresh NullRHI process with `-DisablePlugins=ParisEditorBridge` and no bridge in EnablePlugins. It checks generated classes/dependencies and six persisted mesh/AnimClass/identity configurations, without saving. Success here establishes no runtime bridge dependency at this checkpoint, not packaged-build acceptance.

`ue_character_movement_probe.py` uses rendering-enabled commandlet flags and the bridge. It invokes **the same Blueprint request functions** in a transient Game World with native CharacterMovement/collision, explicit diagnostic local-controller designation, and a fixed timestep of 1/30, 1/60 or 1/120 s. It advances the normal engine frame counter inside the commandlet loop so engine tick tasks and skeletal poses are not suppressed as duplicate work in one outer frame. This is not PIE, keyboard/mouse, AI/NavMesh, city contact, simultaneous six-character performance or a packaged test. It reports numeric movement/capsule/contact and CPU-skinned geometry, and front/side captures at selected 60-step/s checkpoints. A single phase-end image is not a full gait/deformation or foot-slip test.

Evidence is in runtime `Evidence/P2/Movement/`. The first two movement attempts and captures are preserved; v1 capture filenames have PNG suffixes but contain EXR data due to an initially unset render-target format, and are not accepted PNG evidence. Current v3 probing refuses existing report/capture identities; choose a new explicit identity for another run. Inspect JSON assertions and image bytes, not just commandlet exit code. All generated assets remain ignored, unpublished external drafts; the exact Blueprint code allowlist remains unchanged. Adding legacy-axis diagnostic mappings preserves the existing EnhancedInput configuration; physical input still requires its own test.

## P2 reference modes, directional stride and shared lifecycle

`ue_retarget_diagnose.py` is read-only NullRHI with bridge enabled: source/target reference transforms, translation modes, source action names and installed IK APIs. `ue_translation_compare.py` requires rendering-enabled flags because CPU-skinned geometry needs a render MeshObject; the failed NullRHI attempt is preserved in its log. It temporarily compares Animation root/pelvis translation modes and restores originals without saving. Its hashes confirm German source bytes remain unchanged.

`ue_directional_author.py` is a new-only NullRHI authoring pass. It duplicates only the German skeleton/two mesh packages, changing root/pelvis translation modes on the new skeleton, and creates two two-axis AnimBPs/17-sample BlendSpaces. Identical reference proportions made an additional IK-retarget pipeline unnecessary at this checkpoint. `ue_stride_author.py` creates four separately named calibrated copies and derives each moving sample's rate from its matching native root-motion counterpart. CharacterMovement still owns translation; in-place source clips are not changed. Both scripts refuse existing identities; do not rerun over current drafts.

`ue_directional_probe.py` samples complete pose series as well as endpoint captures. Preserve the incomplete multi-case v4 run: five completed numeric cases were followed by a renderer out-of-memory failure. The corrected diagnostic keeps its transient mesh in CPU-skinning mode and flushes end-of-frame render data, avoiding GPU/CPU render-state recreation for every sample. This is a geometry test setting, not the production renderer or a performance pass.

`run_directional_cases.ps1` runs one model/frame-rate case per fresh rendering-enabled process, using distinct v5 reports/capture directories. `-Stride` selects calibrated AnimBPs and distinct v6 identities. It retains already completed same-identity passes and stops on a failed/incomplete report; never silently overwrites or treats a partial set as complete. `review_directional_evidence.py --version v5` (or `v6`) checks all twelve case reports, image headers/sizes and creates derived front/side sheets. Review actual images and residual contact/drift separately; its lower-foot/low-vertical-motion bone drift metric is a heuristic, not a planted-sole detector. Use bundled Python with Pillow for sheets.

`ue_lifecycle_author.py` creates three new child Blueprints and a separate six-Character lifecycle map, leaving old movement drafts intact. Its `-ParisStrideScene=true` mode creates only a new stride-profile map with per-instance mesh/AnimClass overrides; it does not change the previous maps or class defaults. `ue_lifecycle_probe.py` is NullRHI: the same Blueprint damage/death/reset functions on both children, three cycles each. `-ParisStride=true -ParisLifecycleIdentity=probe_stride_v1` separately tests calibrated AnimClass overrides. Ready/Dead ownership and reset invalidation are not a completed weapon action FSM, hit montage, ragdoll, AI or checkpoint snapshot. Death plays a finite existing sequence; reset returns to the prior AnimClass.

`ue_directional_lifecycle_reopen.py` is a bridge-disabled NullRHI fresh-load/hash/dependency/default check for eleven first-stage packages and six saved Characters. Fresh mode evidence is separately recorded by the v5 processes. Calibrated copies/new scene need their own fresh-load pass. `inventory_local_drafts.py` prints SHA/size/path metadata only; any retained source copy must stay explicitly unselected/unpublished. It does not upload assets, alter Catalog, whitelist Blueprint bytes or grant restore authority.

The later fresh pass uses `-ParisStride=true -ParisReopenIdentity=stride_reopen_v1` and checks sixteen packages plus the calibrated scene's six per-instance overrides. Existing report identities are refused. See the dated directional/lifecycle result and weapon capability review in `Docs/Development/`; read their remaining gates rather than treating generation or a numeric pass as full presentation acceptance.

## P3 read-only capability checks

`ue_weapon_capability_audit.py` inventories native mesh rigs/materials, selected action tracks/notifies and source root-motion speeds. Empty Blueprint candidates and absent named FP assets are inventory findings, not proof that full-body first person is impossible. Do not read protected animation Notifies directly; use the installed AnimationLibrary event-name API.

`ue_fullbody_view_probe.py` loads the diagnostic map, changes only unsaved actor/camera/pose/head visibility and captures an empty-handed eye-level candidate at 90-degree horizontal FOV. It checks the saved map hash afterwards. V1 positional Rotator arguments accidentally treated the requested down-look value as roll; preserve it but do not claim down-look acceptance. V2 uses explicit pitch/yaw/roll keywords and a 1 cm capture-only near plane. Neither establishes accepted weapon grip, sights, first-person quality, reload mechanics or actual player input. Preserve original/native packages and inspect the images before recording a result.
